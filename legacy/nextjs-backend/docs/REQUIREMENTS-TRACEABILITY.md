## Responsible-design rules compliance

- **Human authority** — accept/reject, priority override, routing decision, reassignment, mediation outcome, closure: all human actions with recorded authority (`onWhoseAuthority` in audit).
- **Provenance** — 5-tag vocabulary on entries and documents, visible everywhere.
- **Privacy/safety** — collect-minimal forms; RBAC; safe contact; sensitive access logs.
- **Accessibility** — see G4.
- **Failure handling** — no silent spinners: AI-unavailable, conflict, blocked, overdue, escalated states all render explicitly.
- **Workflow fit** — every module writes to the same spine; coverage counts prove integration.
- **Sample data** — illustrative banner on every screen; masked NID refs (`nidRef`), seeded names only.

## Deliberate scope decisions (conservative resolutions of PDF ambiguities)

1. "16699/IVR" is a **simulated voice door** (speech synthesis + keypad + transcript) — the PDF explicitly allows labelled simulation for integrations that cannot be connected live; no live call is claimed.
2. "Marma language" is represented by an **illustrative verbatim field** (`originalText`) — translation itself remains human (UDC), which is the PDF's provenance point.
3. Payment amounts/stages are **tracked, not computed** — no invented law about legal-aid fee schedules.
4. E-signature is a **prototype integrity mechanism** — the PDF's own guardrail is reproduced verbatim in the UI.
5. Eligibility is **never decided by AI or rules** — the checklist compares documents only; acceptance/rejection remain officer decisions with reasons.
