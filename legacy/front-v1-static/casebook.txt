Can one digital legal-aid architecture serve five very different citizens, support seven different provider

Build one integrated DLAS prototype that incorporates ALL five Part A citizen scenarios, ALL seven Part B provider
scenarios, and ALL eleven targeted technical challenges. The prototype must use one shared record architecture,
common services and a traceable workflow rather than separate mini-projects.

The common backbone

ENTRY CHANNEL -> APPLICATION ID -> VERIFICATION / REVIEW -> CASE ID -> MEDIATION / LAWYER /
                      REFERRAL / OTHER SERVICE -> FOLLOW-UP -> OUTCOME -> CLOSURE

· An Application ID is created at submission.
· A Case ID is created only after acceptance and remains with the case through referral, mediation, lawyer

     assignment and closure.
· Contact-safety rules, representation status, document history, permissions and audit history follow the record.
· Every provider uses a role-appropriate view of the same authoritative record.
· Every technical module must write back to the same record rather than create a disconnected side system.

RESPONSIBLE-DESIGN RULES

Area                             Non-negotiable rule

Human authority                  Eligibility, rejection, final priority, legal judgment, consequential referral, final lawyer assignment, mediation outcome
                                 and closure remain with authorised humans.

Provenance                       Applicant-confirmed, representative-reported, intermediary-translated, staff-entered and AI-inferred information must be
                                 distinguishable.

Privacy / safety                 Collect only what is needed; apply role-based access; enforce safe contact; keep material access/change history.

Accessibility                    Bangla-first demonstrated interfaces; accessible labels, focus, errors and zoom; equivalent route where a visual-only
                                 step would exclude.

Failure handling                 Every module must fail visibly and safely through uncertainty, retry, handoff, escalation or human review rather than
                                 silent error.

Workflow fit                     Every module must connect to the same DLAS record, IDs, tasks and audit history.

Sample data                      Use illustrative data only. Do not use real NID numbers, real cases, real beneficiary records, live payments or a live
                                 16699 call.
